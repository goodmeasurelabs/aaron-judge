# Release verification

Pull requests validate without deployment credentials. Successful pushes to the current main commit rebuild and publish to the existing Worker through the inherited organization secret `CLOUDFLARE_DEPLOY_TOKEN`. GitHub secret-name metadata confirms that this existing secret is available; no credential was created or copied.

The release retains `--keep-vars` and does not manage domain routes in Wrangler. Before upload it verifies the fixed account/Worker identity and records active deployment/version IDs, binding names/types, compatibility metadata, custom domains and Worker routes. The candidate GitHub SHA is labelled `requestedSourceSha`; it does not claim that production already serves that commit. After upload, verification reads the active Worker version annotation for exact commit proof, requires 100% traffic, and compares protected metadata with the before snapshot. Resulting sanitized after-state is saved even if those assertions fail. Actions retains evidence for 30 days. No configuration or secret values are persisted.

The first production merge remains a coordinated release decision. Keep existing provider hosting and current Worker versions for rollback. A dry run or homepage HTTP 200 alone does not prove deployment/source parity. Existing provider integrations, DNS, service secrets and unrelated repository changes require their own explicit scope.
